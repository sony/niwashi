# Nodes in Detail

This page provides a detailed explanation of all Node attributes and how to use them.

## What Is a Node?

A Node is an individual logical unit of computation that makes up the system. Each Node has an identifier (key) and attributes that specify what the Node should have.

---

## Basic Node Definition

The simplest Node definition specifies only an identifier:

```yaml
inventory:
  nodes:
    node1: {}
    node2: {}
    node3: {}
```

---

## Node Attributes

The following attributes can be specified for a Node.

### labels

Attaches labels (metadata) to a Node. Labels are specified as string key-value pairs.

```yaml
inventory:
  nodes:
    web-server:
      labels:
        role: web
        environment: production
        region: us-east-1
```

#### Uses

- Classifying or identifying Nodes (task filtering with the `where` field)
- Attaching metadata

Labels defined here can be referenced in recipe task `where` fields.

```yaml
# Example of referencing node.labels.role on the recipe side
tasks:
  - name: configure-web
    where: "node.labels.role == 'web'"
    action:
      exec.remote:
        scriptTpl: |
          echo "Configuring web server"
```

See [Task Filtering Condition (where)]({{< relref "../defining-recipes/task-where" >}}) for details.

---

### capabilities

Specifies the Capabilities (functions) that the Node should have. A Capability is a unit of functionality realized by a Recipe.

#### Short form (string only)

```yaml
inventory:
  nodes:
    db-server:
      capabilities:
        - database.postgresql
        - monitoring.prometheus-node-exporter
```

#### Long form (with parameters)

```yaml
inventory:
  nodes:
    web-server:
      capabilities:
        - id: web.nginx
          params:
            port: 8080
            worker_processes: 4
```

#### Specifying Multiple Capabilities

Multiple Capabilities can be specified for a Node:

```yaml
inventory:
  nodes:
    app-server:
      capabilities:
        - runtime.python
        - web.nginx
        - monitoring.prometheus-exporter
        - logging.fluentd
```

Capabilities are applied in the order specified.

#### Capability Details

For details on how to specify Capabilities and Recipes, see [Capabilities and Recipes in Detail]({{< relref "capabilities" >}}).

---

### templates

Nodes can be defined by inheriting from templates. Multiple templates can be specified as an array.

```yaml
template:
  node:
    base:
      labels:
        environment: production

inventory:
  nodes:
    web-server:
      templates: [base]
      capabilities:
        - web.nginx
```

#### Applying Multiple Templates

```yaml
template:
  node:
    base:
      labels:
        managed_by: niwashi

    web-base:
      capabilities:
        - monitoring.prometheus-exporter

inventory:
  nodes:
    web-01:
      templates: [base, web-base]
      capabilities:
        - web.nginx
```

Templates specified later override the settings of earlier templates.

See [Templates in Detail]({{< relref "templates" >}}) for more information.

### instanceSelector

Nodes must be bound to actual physical machines or virtual machines (instances). The `instanceSelector` controls this binding.

#### Automatic Selection (not specified)

When `instanceSelector` is not specified, Niwashi automatically selects an available (not yet assigned) instance.

```yaml
inventory:
  nodes:
    node1: {}
    node2: {}
```

#### Specifying a generator

Automatically selects from instances created by a specific Generator:

```yaml
inventory:
  nodes:
    vm-node:
      instanceSelector:
        generator: my-vm-generator
```

In this example, an unassigned instance generated by `my-vm-generator` is automatically selected.

#### Specifying generator + instance

Explicitly specify a particular instance from a particular Generator:

```yaml
inventory:
  nodes:
    specific-node:
      instanceSelector:
        generator: my-vm-generator
        instance: vm-01
```

#### Behavior When Assignment Fails

If instance assignment fails (no available instances, the specified Generator does not exist, etc.), Niwashi returns an error and Plan execution is aborted.

## Relationship Between Nodes and Instances

### Concept

```
┌───────────────────┐
│  Node (logical)   │
│  web-server       │  Logical unit of computation
└─────────┬─────────┘
          │ assignment
          ↓
┌─────────┴─────────┐
│  Instance (real)  │
│  192.168.1.10     │  Actual compute resource
└───────────────────┘
```

- **Node**: A logical request such as "a web server is needed"
- **Instance**: A physical entity such as "the virtual machine at 192.168.1.10"

### How Automatic Assignment Works

Niwashi processes instance assignment in the following priority order. By processing nodes with more specific selectors first, it prevents them from interfering with nodes that have no explicit assignment.

1. Nodes with both `generator` and `instance` specified are processed first (the specific instance is reserved)
2. Nodes with `generator` only are processed next (selects from unassigned instances of that Generator)
3. Nodes with no `instanceSelector` are processed last (selects from all unassigned instances)

If no available instance exists, an error is returned.

### Example

```yaml
infrastructure:
  generators:
    web-vms:
      provisioner: infra.vm.driver=vagrant
      params:
        count: 3  # Generate 3 instances

    db-vms:
      provisioner: infra.vm.driver=vagrant
      params:
        count: 1  # Generate 1 instance

inventory:
  nodes:
    web-primary:
      instanceSelector:
        generator: web-vms
        instance: nws-vm-0  # Reserve this specific instance first

    web-01:
      instanceSelector:
        generator: web-vms  # Auto-select from unassigned instances in web-vms

    web-02:
      instanceSelector:
        generator: web-vms  # Auto-select from unassigned instances in web-vms

    db-01:
      instanceSelector:
        generator: db-vms   # Auto-select from unassigned instances in db-vms
```

## Practical Node Definition Examples

### Simple Node

```yaml
inventory:
  nodes:
    worker-01: {}
```

Identifier only. All attributes use defaults.

### Node with Labels

```yaml
inventory:
  nodes:
    web-server:
      labels:
        role: web
        tier: frontend
        environment: production
```

Attaches metadata.

### Node with Capabilities

```yaml
inventory:
  nodes:
    db-server:
      capabilities:
        - database.postgresql
        - monitoring.prometheus-exporter
```

Specifies multiple Capabilities.

### Capability with Parameters

```yaml
inventory:
  nodes:
    app-server:
      capabilities:
        - id: runtime.python
          params:
            version: "3.11"
        - id: web.nginx
          params:
            port: 8080
            worker_processes: 4
```

Passes parameters to each Capability.

### Specifying a Generator

```yaml
inventory:
  nodes:
    high-spec-node:
      capabilities:
        - database.postgresql
      instanceSelector:
        generator: high-spec-vms
```

Uses an instance from a specific Generator.

### Using a Template

```yaml
template:
  node:
    production-base:
      labels:
        environment: production
        managed_by: niwashi

inventory:
  nodes:
    web-01:
      templates: [production-base]
      capabilities:
        - web.nginx
```

Inherits common settings from a template.

### Complete Example

An example using all attributes:

```yaml
template:
  node:
    base:
      labels:
        environment: production

inventory:
  nodes:
    app-server:
      templates: [base]
      labels:
        role: application
        tier: backend
      capabilities:
        - id: runtime.python
          params:
            version: "3.11"
        - id: web.nginx
          params:
            port: 8080
        - monitoring.prometheus-exporter
      instanceSelector:
        generator: app-vms
```

## Common Patterns

### Web Server Node

```yaml
inventory:
  nodes:
    web-01:
      labels:
        role: web
      capabilities:
        - web.nginx
        - monitoring.prometheus-exporter
```

### Database Node

```yaml
inventory:
  nodes:
    db-primary:
      labels:
        role: database
        replication: primary
      capabilities:
        - id: database.postgresql
          params:
            version: "15"
            max_connections: 200
```

### Application Node

```yaml
inventory:
  nodes:
    app-server:
      labels:
        role: application
      capabilities:
        - runtime.python
        - web.gunicorn
        - monitoring.prometheus-exporter
```

### Cache Node

```yaml
inventory:
  nodes:
    cache-server:
      labels:
        role: cache
      capabilities:
        - id: cache.redis
          params:
            max_memory: "1GB"
```

## Troubleshooting

### Instance Not Assigned

**Problem**: An error occurs because no instance is assigned to a Node.

**Causes**:
- Insufficient available instances
- The Generator specified in `instanceSelector.generator` does not exist
- The Generator is not generating enough instances

**Solutions**:
1. Increase `params.count` in the Generator
2. Verify the `instanceSelector.generator` specification
3. Check the Generator definition

### Capability Not Applied

**Problem**: A Capability was specified for a Node but it does not work as expected.

**Causes**:
- The Recipe ID is incorrect
- Parameters are missing
- The Recipe cannot be found

**Solutions**:
1. Check the spelling of the Recipe ID
2. Check the Recipe documentation for required parameters
3. Verify that the Recipe is correctly installed

# Infrastructure Basics

The `infrastructure` section defines how physical/virtual Infrastructure is generated. It is where you describe "where to deploy".

## Infrastructure Structure

```yaml
infrastructure:
  generators:
    # Definition of instance Generators
```

- **generators**: Definitions of Generators that create and manage instances (virtual machines, containers, existing servers, etc.)

---

## Generators

A Generator is a definition for creating and managing instances. Each Generator must specify a `provisioner` that determines how instances are generated.

### Basic Definition

A minimal Generator definition:

```yaml
infrastructure:
  generators:
    my-generator:
      provisioner: external-instance
```

This example uses the built-in provisioner `external-instance`.

### Generator Identifiers

Each Generator is given a unique identifier (key):

```yaml
infrastructure:
  generators:
    web-vms: {}
    db-vms: {}
    cache-vms: {}
```

For identifier naming rules, see [Identifier Naming Rules]({{< relref "naming-rules" >}}).

---

## Generator Attributes

### provisioner (required)

The Recipe ID specifying how instances are generated. The type of provisioner determines the nature of the instances that are created.

```yaml
infrastructure:
  generators:
    vms:
      provisioner: infra.vm.driver=vagrant
```

For details on how to specify the provisioner Recipe ID, see [Capabilities and Recipes in Detail]({{< relref "../capabilities" >}}).

### params

Specifies provisioner-specific parameters. The content of the parameters differs depending on the Provisioner Recipe used.

```yaml
infrastructure:
  generators:
    vagrant-vms:
      provisioner: infra.vm.driver=vagrant
      params:
        count: 3
        box: ubuntu/jammy64
        cpus: 2
        memory: 2048
```

## What Is an Instance?

An **instance** is the actual compute resource assigned to a Node:

- Virtual machine (VM)
- Container
- Existing physical server
- Cloud instance

Generators create and manage these instances.

### Relationship Between Instances and Nodes

```
┌─────────────────┐
│  Inventory      │
│  ┌───────────┐  │
│  │ Node      │  │  Logical unit of computation
│  └─────┬─────┘  │
└────────┼────────┘
         │ assignment
         ↓
┌────────┼────────┐
│  Infrastructure │
│  ┌─────┴─────┐  │
│  │ Instance  │  │  Actual compute resource
│  └───────────┘  │
└─────────────────┘
```

- **Node**: A logical unit of computation (the concept of "a web server is needed")
- **Instance**: An actual compute resource (the entity of "the virtual machine at 192.168.1.10")

Niwashi automatically assigns instances generated by Generators to Nodes.

## Built-in Provisioners

Niwashi provides special built-in provisioners.

### external-instance

Used when utilizing already-running external machines or servers as instances.

```yaml
infrastructure:
  generators:
    existing-servers:
      provisioner: external-instance
      params:
        instances:
          server-01:
            connection:
              ssh:
                address:
                  host: 192.168.1.10
                  port: 22
                  user: ubuntu
                auth:
                  method: privateKey
                  privateKeyPath: ~/.ssh/id_rsa
          server-02:
            connection:
              ssh:
                address:
                  host: 192.168.1.11
                  port: 22
                  user: ubuntu
                auth:
                  method: privateKey
                  privateKeyPath: ~/.ssh/id_rsa
```

This example registers two already-running servers (`server-01` and `server-02`) as instances. See [Connections in Detail]({{< relref "../connections" >}}) → [SSH Connection Reference]({{< relref "../connection-ssh" >}}) for the full field reference.

Windows nodes use the `winrm` connection type instead of `ssh`:

```yaml
infrastructure:
  generators:
    existing-servers:
      provisioner: external-instance
      params:
        instances:
          windows-server-01:
            connection:
              winrm:
                address:
                  host: 192.168.1.20
                  user: Administrator
                auth:
                  method: ntlm
                  passwordRef:
                    fromEnv: WINDOWS_ADMIN_PASSWORD
```

This example registers a Windows machine (a standalone, non-domain-joined host) as an instance. See [Connections in Detail]({{< relref "../connections" >}}) → [WinRM Connection Reference]({{< relref "../connection-winrm" >}}) for the full field reference and constraints.

### Uses of external-instance

- Utilizing existing cloud instances
- Utilizing existing in-house servers
- Adding manually set up environments to management

## Reference Provisioners

In addition to built-in provisioners, Niwashi provides reference provisioner Recipes.

### Vagrant

Generates virtual machines locally:

```yaml
infrastructure:
  generators:
    local-vms:
      provisioner: infra.vm.driver=vagrant
      params:
        count: 3
        box: ubuntu/jammy64
        cpus: 2
        memory: 2048
```

#### Example Vagrant Provisioner Parameters

- **count**: Number of instances to generate
- **box**: Vagrant box to use
- **cpus**: Number of CPUs
- **memory**: Memory (MB)
- **disk_size**: Disk size
- **network**: Network settings

For details, refer to the Vagrant Recipe documentation.

## How to Use Generators

### Basic Usage

1. Define a Generator
2. Reference from Nodes (optional)

```yaml
infrastructure:
  generators:
    vms:
      provisioner: infra.vm.driver=vagrant
      params:
        count: 3

inventory:
  nodes:
    node1:
      instanceSelector:
        generator: vms  # Explicitly specify Generator
    node2: {}           # Automatic selection
    node3: {}           # Automatic selection
```

### Multiple Generators

Multiple Generators can be defined for different purposes:

```yaml
infrastructure:
  generators:
    # For web servers (lower spec)
    web-vms:
      provisioner: infra.vm.driver=vagrant
      params:
        count: 2
        box: ubuntu/jammy64
        cpus: 1
        memory: 1024

    # For DB servers (higher spec)
    db-vms:
      provisioner: infra.vm.driver=vagrant
      params:
        count: 1
        box: ubuntu/jammy64
        cpus: 4
        memory: 4096

inventory:
  nodes:
    web-01:
      instanceSelector:
        generator: web-vms
    web-02:
      instanceSelector:
        generator: web-vms
    db-01:
      instanceSelector:
        generator: db-vms
```

## Practical Examples

### Local Development Environment

```yaml
infrastructure:
  generators:
    local-vms:
      provisioner: infra.vm.driver=vagrant
      params:
        count: 3
        box: ubuntu/jammy64
        cpus: 2
        memory: 2048

inventory:
  nodes:
    web: {}
    app: {}
    db: {}
```

### Managing Existing Servers

```yaml
infrastructure:
  generators:
    prod-servers:
      provisioner: external-instance
      params:
        instances:
          web-prod:
            connection:
              ssh:
                address:
                  host: web.example.com
                  port: 22
                  user: deploy
                auth:
                  method: privateKey
                  privateKeyPath: ~/.ssh/deploy_key
          db-prod:
            connection:
              ssh:
                address:
                  host: db.example.com
                  port: 22
                  user: deploy
                auth:
                  method: privateKey
                  privateKeyPath: ~/.ssh/deploy_key

inventory:
  nodes:
    web:
      instanceSelector:
        generator: prod-servers
    db:
      instanceSelector:
        generator: prod-servers
```

### Mixed Environment

Using different provisioners for development and production:

#### base.yaml (common logical configuration)

```yaml
version: nws.state/v1

inventory:
  nodes:
    web:
      capabilities:
        - web.nginx
    db:
      capabilities:
        - database.postgresql
```

#### infra-dev.yaml (development environment)

```yaml
version: nws.state/v1

infrastructure:
  generators:
    local-vms:
      provisioner: infra.vm.driver=vagrant
      params:
        count: 2
        box: ubuntu/jammy64
```

#### infra-prod.yaml (production environment)

```yaml
version: nws.state/v1

infrastructure:
  generators:
    prod-servers:
      provisioner: external-instance
      params:
        instances:
          web-prod:
            connection:
              ssh:
                address:
                  host: web.example.com
                  port: 22
                  user: deploy
          db-prod:
            connection:
              ssh:
                address:
                  host: db.example.com
                  port: 22
                  user: deploy
```

#### Switching Between Them

```bash
# Development environment
nwsctl plan -t base.yaml -t infra-dev.yaml

# Production environment
nwsctl plan -t base.yaml -t infra-prod.yaml
```

## Instance Assignment

There are multiple ways to assign instances to Nodes.

### Automatic Assignment

When `instanceSelector` is not specified, available instances are automatically selected:

```yaml
inventory:
  nodes:
    node1: {}  # Automatic assignment
    node2: {}  # Automatic assignment
```

### Specifying a Generator

Selects from instances generated by a specific Generator:

```yaml
inventory:
  nodes:
    web-node:
      instanceSelector:
        generator: web-vms
```

See [Nodes in Detail]({{< relref "../nodes" >}}) for more information.

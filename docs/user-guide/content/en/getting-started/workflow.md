# Workflow

This section describes the basic working flow when using Niwashi.

---

## Basic Workflow

Work with Niwashi consists of the following steps:

1. **Preparation**: Set up Recipes
2. **Initialization**: Create a Workspace (`nwsctl init`)
3. **Define the desired state**: Describe it in a YAML file
4. **Create a Plan**: Generate an execution plan (`nwsctl plan`)
5. **Execute the Plan**: Apply the changes (`nwsctl apply`)

---

## Preparation: Setting Up Recipes

Before using Niwashi, set up the required Recipes locally.

### Obtaining Recipes

```bash
# Create a working directory
mkdir -p ~/niwashi-project
cd ~/niwashi-project

# Clone the Recipe repository
git clone <recipe-repository-url> recipes
```

If you are using reference Recipes, specify `${REFERENCE_RECIPE_REPO}`. If you have your own Recipe repository, specify its URL.

### Example Recipe Directory Structure

```
~/niwashi-project/
├── recipes/          # Recipe directory
│   ├── ansible/
│   ├── kubernetes/
│   └── vagrant/
└── state.yaml        # Desired state file (created later)
```

---

## Step 1: Initialization

### Initializing a New Project

To start a new project:

```bash
nwsctl init
```

This creates the Niwashi Workspace (default: `.niwashi`).

### Importing an Existing State

To import an existing state:

```bash
nwsctl init -s existing-state.yaml
# or
nwsctl init --state existing-state.yaml
```

---

## Step 2: Defining the Desired State

Describe the desired state in a YAML file.

Example: `state.yaml`

```yaml
version: nws.state/v1

inventory:
  nodes:
    web-server:
      capabilities:
        - web.nginx

infrastructure:
  generators:
    vms:
      provisioner: infra.vm.driver=vagrant
      params:
        count: 1
```

For details, see [Defining State]({{< relref "defining-desired-state" >}}).

---

## Step 3: Creating a Plan

Create an execution plan from the desired state:

```bash
nwsctl plan \
  --recipe-dir ./recipes \
  -t state.yaml
```

**Options**:
- `--recipe-dir`: Directory containing Recipes (can be specified multiple times)
- `-t, --target`: Desired state file (can be specified multiple times)

Niwashi compares the current state with the desired state and plans the necessary changes.

### Merging Multiple State Files

You can create a Plan by merging multiple files:

```bash
nwsctl plan \
  --recipe-dir ./recipes \
  -t infra-dev.yaml \
  -t app.yaml
```

Files are merged from left to right.

### Specifying Multiple Recipe Directories

```bash
nwsctl plan \
  --recipe-dir ./recipes \
  --recipe-dir ./custom-recipes \
  -t state.yaml
```

---

## Step 4: Executing the Plan

Execute the Plan to realize the desired state:

```bash
nwsctl apply \
  --plan plan.json \
  --recipe-dir ./recipes
```

**Options**:
- `--recipe-dir`: Directory containing Recipes (can be specified multiple times)
- `--plan`: Plan file to execute (required)

Niwashi executes infrastructure provisioning and configuration management according to the Plan.

---

## Deleting Resources

### Creating a Destroy Plan

Create a Plan to delete all resources:

```bash
nwsctl plan \
  --recipe-dir ./recipes \
  --destroy
```

Specifying the `--destroy` flag treats the desired state as empty and generates a Plan to delete all current resources.

### Executing the Destroy Plan

Execute the generated destroy Plan. To apply a destroy plan, the `--destroy` flag is also required on `apply`:

```bash
nwsctl apply \
  --plan plan.json \
  --recipe-dir ./recipes \
  --destroy
```

A confirmation prompt is displayed asking whether it is safe to delete resources (you can skip it by adding `--yes`). Niwashi deletes resources according to the Plan.

### Notes

- **Recipe support**: Not all Recipes support deletion. Depending on the Recipe, resources may not be deleted correctly.
- **Verification**: Review `plan.json` before deletion to confirm that no unintended resources will be removed.
- **Backup**: It is recommended to back up important data beforehand.

## Workspace and State Management

### Workspace Location

Niwashi saves the following to the Workspace (specified with `--work-dir`):

- **Current state**: The current state managed by Niwashi
- **Recipe data**: Files and data generated by Recipes

Default Workspace: `.niwashi` (under the current directory)

### Managing Current State

The current state is under Niwashi's management and cannot be edited directly. To change the state, define a desired state and run `plan` → `apply`.

### Constraints on export/import

It is possible to export the current state with `nwsctl export` and import it into another Workspace with `init -s`, but some Recipes may not work correctly after doing so.

**Example**: The Vagrant Recipe creates VM images and other files under the Workspace. Since these files are not included in the export, re-provisioning may be required after importing.

## Typical Usage Patterns

### Development Cycle

```bash
# 1. Modify the desired state (edit state.yaml)

# 2. Review the Plan
nwsctl plan --recipe-dir ./recipes -t state.yaml

# 3. Apply
nwsctl apply --plan plan.json --recipe-dir ./recipes

# 4. Verify behavior

# 5. Return to step 1
```

### Switching Environments

```bash
# Development environment
nwsctl plan --recipe-dir ./recipes -t infra-dev.yaml -t app.yaml
nwsctl apply --plan plan.json --recipe-dir ./recipes

# Production environment
nwsctl plan --recipe-dir ./recipes -t infra-prod.yaml -t app.yaml
nwsctl apply --plan plan.json --recipe-dir ./recipes
```
